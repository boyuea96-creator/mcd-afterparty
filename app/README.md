# 麦麦散场局 · 本机版

散场之后这顿饭怎么吃 —— 填五个空，出一套真价、真路线的方案。

不是演示稿。价格和套餐是麦当劳 MCP 实时试出来的，距离和耗时是高德实时算的。

---

## 跑起来

```bash
cd app
python3 server.py          # 或者双击「启动.command」
```

然后打开 <http://127.0.0.1:8765>。换端口：`python3 server.py 9000`。

不需要 `pip install` 任何东西 —— 只用 Python 标准库。

### 需要两样东西

| 东西        | 从哪来                                                                  | 没有会怎样        |
| --------- | -------------------------------------------------------------------- | ------------ |
| 麦当劳 token | 已有的 `~/.workbuddy/mcp.json` 里的 `mcd-mcp.headers.Authorization`，自动读   | 直接跑不了，出不了价   |
| 高德 key    | `AMAP_KEY` 环境变量 → `~/.zcode/amap.key` → `mcp.json` 里的 `amap-mcp` url | 价格照算，交通那一段跳过 |

token 只在内存里用，不写文件、不进日志、不进接口返回。

## 它是怎么算的

```
填表
 └─ 地址 → 高德地理编码（拿到经纬度 + 城市 + 街道）
     └─ 找店：街道词 / 商圈词 / 麦当劳 POI 名 多路并发查
         └─ 门店经纬度全是 0.0 → POI 坐标 或 门店地址反查，再算真实步行距离
             └─ 按距离排队，逐个验菜单（有的关门、有的不支持到店自取，自动降级）
                 ├─ 堂食：菜单 → 枚举买法 → 分批并发试价 → 取最低
                 │         + 券三源 + 麦金卡两次试价 + 两段交通
                 └─ 外卖：账号已存地址 → 外送门店 → 菜单 → 试价（已含运费打包）
                           + 你自己过去那一段的对照
```

几个容易踩的坑，这里都处理了：

- **`query-meals` 用的是「现在」**。所以散场时间在未来时，会带 `reservationDate` 去查那一刻的菜单和价格；已经过去了就按现在算，并在页面上说明。
- **`calculate-price` 的 `items` 用 `productCode`，不是 `code`**。写错不报错，只是价格返回 0。
- **价格单位是分**。`4470` 是 ¥44.70。
- **打车价要 `extensions=all` 且读 `route.taxi_cost`**，所以高德走 REST 不走 MCP（MCP 不暴露 `extensions`）。
- **券类接口返回的是 markdown 不是 JSON**，`query-my-coupons` / `available-coupons` 要单独解析。
- **麦金卡必须两次试价取差**，不能拿划线价当省额。

## 文件

```
app/
  server.py       HTTP 服务（纯标准库，绑 127.0.0.1）
  engine.py       决策计算：找店 / 买法枚举 / 试价 / 券 / 交通 / 一句话
  mcpc.py         麦当劳 MCP 客户端 + 高德 REST 客户端
  index.html      两屏页面（读 /api/plan 的 JSON 渲染）
  启动.command    双击启动
```

### 接口

| 方法   | 路径               | 干什么                 |
| ---- | ---------------- | ------------------- |
| GET  | `/`              | 两屏页面                |
| GET  | `/api/health`    | 拉一次工具列表，确认 token 活着 |
| GET  | `/api/addresses` | 读账号里存的外送地址（只读）      |
| POST | `/api/plan`      | 填表 → 两套账            |

`POST /api/plan` 的入参：

```json
{
  "from_addr": "浙江省杭州市滨江区飞虹路3号",
  "to_addr":   "浙江省杭州市滨江区飞虹路208号",
  "when":      "2026-10-19 21:30",
  "people":    3,
  "form":      "dinein | delivery | undecided",
  "taste":     "想吃麦辣鸡翅 / 不想吃冰的",
  "budget":    "40",
  "rel":       "同事",
  "tired":     "适中 | 疲劳 | 轻松"
}
```

页面也支持深链预填，方便分享一次查询：

```
http://127.0.0.1:8765/?from=…&to=…&people=3&form=undecided&go=1
```

## 只读

允许的工具只有查询类和一价计算：

`query-nearby-stores` `delivery-query-addresses` `delivery-query-stores` `query-meals`  
`calculate-price` `query-store-coupons` `query-my-coupons` `available-coupons`  
`now-time-info` + 高德的地理编码 / 路径规划

**七个写操作一个都没调**：下单、取消、领券、建地址、抽奖、兑换、团餐下单。  
`calculate-price` 是唯一一个"逆向"的动作，它只算钱，不产生订单。

## 已知边界

- **外卖只认 App 里已存过的地址。** 建地址工具是禁用的，所以填一个没存过的地址会明确告诉你「先去 App 加一个」，不会替你建。
- **外卖的送达时刻算不出来。** MCP 不返回 ETA，页面写的是「以下单页为准」，不编。
- **门店经纬度接口给的是 `0.0`**，所以坐标靠 POI 或地址反查。实在定不准会说明「这段路没算」，不会硬编一个数。
- **到店自取不支持的门店会自动跳过**（比如开在商场 B1 的、甜品站）。
- **买法是从菜单里自动发现的**，不是写死的 SKU。所以不同城市、不同时段，能给出的最低组合会不一样 —— 那是真的不一样，不是 bug。
- 到手温度、脆度这类，是按常识判断的，不是接口数据，页面上标了「打问号」。

## 和 skill 的关系

这个程序是**决策体系的可执行版本**。逻辑跑通、边界摸清之后，再把这些规则写回  
`.workbuddy/skills/mcd-afterparty/SKILL.md`，让 WorkBuddy 里说一句「麦麦散场局」就能触发。

程序先做，是因为有些事只有真跑才知道 —— 比如「最近的店可能点不出餐」这种，  
光看接口文档写不出来。
